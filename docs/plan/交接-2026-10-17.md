## 关键决策与数值（别重新拍脑袋）

### 设计稿就是摆放真相源

`docs/design/五行关卡设计v3.html` 里每境有一张 `<svg class="map-svg">` 侧视图。
**它画的就是最终布局**。之前的场景不是照着它做的，机关位置逐段右漂
（木境：前两段精确，段 3 起 +327 → 灵泉 **+1234**）。

### 纵向换算系数 = 4.0

- 横向：`sx = levelRight / svgWidth`（木境 8832/1700 ≈ 5.20）
- **纵向单独取 4.0**，不是 sx。理由：设计稿台阶高 30 SVG 单位，
  用 sx 会得到 156 世界单位，而一次跳跃只有 `v²/2g = 320²/(2×320) = 160`
  —— 几乎顶满，跳不上去。取 4.0 → 台阶 120，留余量。
- 基准：SVG 地面顶线 `y=250` ↔ 世界 `-295`（沿用旧 `LevelDirector.GroundTopY`）

### 相机可见范围与固定高度

- 相机在 Host 场景摆在 `y=0`、正交半高 360 → 可见 `y ∈ [-360, 360]`
- 旧 `Sync()` **只跟 x**，所以摆在 `y < -360` 的内容永远看不见
  （岩浆 −820、水流 −700 都是这样）
- 现在支持纵向跟随，但**没填边界就等于没启用**

## 工作方式上的经验（这一轮踩的）

- **场景 YAML 读不到 prefab 实例**：实例只存 `m_Modifications`，组件在 prefab 里。
  判断"有没有渲染 / 字段值"要用 RQL 查引擎。`m_EditorClassIdentifier` 是改名残留，认 GUID。
- **`SerializedObject.objectReferenceValue` 会静默丢值**：往 `GameObject` 字段塞
  `Transform`，不报错、直接留 null。必须按字段声明类型转换并回读校验。
- **挑美术先量 alpha**：全不透 = 材质不是精灵，当 sprites 用就是一块方板。
  这一轮因此误判过两次（`fx_crack`、`fx_flame`）。
