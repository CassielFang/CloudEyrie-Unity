## 关键决策与数值（别重新拍脑袋）

### 设计稿就是摆放真相源

`docs/design/五行关卡设计v3.html` 里每境有一张 `<svg class="map-svg">` 侧视图。
**它画的就是最终布局**。之前的场景不是照着它做的，机关位置逐段右漂
（木境：前两段精确，段 3 起 +327 → 灵泉 **+1234**）。

### 纵向换算系数 = 4.0

- 横向：`sx = levelRight / svgWidth`（木境 8832/1700 ≈ 5.20）
- **纵向单独取 4.0**，不是 sx。理由：设计稿台阶高 30 SVG 单位，
  用 sx 会得到 156 世界单位，而一次跳跃只有 `v²/2g = 320²/(2×320) = 160`
  —— 几乎顶满，跳不上去。取 4.0 → 台阶 120，留余量。
- 基准：SVG 地面顶线 `y=250` ↔ 世界 `-295`（沿用旧 `LevelDirector.GroundTopY`）

### 相机可见范围与固定高度

- 相机在 Host 场景摆在 `y=0`、正交半高 360 → 可见 `y ∈ [-360, 360]`
- 旧 `Sync()` **只跟 x**，所以摆在 `y < -360` 的内容永远看不见
  （岩浆 −820、水流 −700 都是这样）
- 现在支持纵向跟随，但**没填边界就等于没启用**

## 续做（同一天，第三轮）：背景飘移 / 相机出画 / 地面视觉

玩家实测反馈的两个问题，都已定位并修掉：

### 1. 背景「慢慢飘走」

- 开场 cue 的 `autoPanSpeed = 18` 是**单方向累加**，玩家不走到 `atX=420` 就一直推；
- `MaxPan()` 的余量公式符号写反（`+ factor × travel` 应为 `−`），算出的可推距离比真实余量大几百；
- 换关不重置 `_pan`。

修复（`ParallaxBackground.cs`）：
- 新增 `autoPanLimit = 120`（硬上限；推这么远就停）；
- `MaxPan` 改用 `actualW − LayerWidth`；
- `ApplyTheme` 里 `_pan = 0`。
- 顺带修了 `LevelHost` 调 `ApplyTheme` 时把**关卡两端**当成**相机行程**传进去的问题（现在传 `levelLeft + halfView`）。

### 2. 相机有时把角色留在视野外

三个原因：
1. **纵向跟随没启用**：六关 `LevelDefinition.asset` 的 `levelBottom/levelTop` 都是 0；
2. 玩家掉进**没有 Hazard 安全网**的坑时会一直往下掉（工程没有全局 kill plane）；
3. `CameraFollow` 的纵向死区是按「目标空间」算的，偏移 275 + 死区 200 会让角色离相机中心 475，而半屏只有 360。

修复：
- `CameraFollow`：新增 `verticalOffset = 275`（站在地面时相机回到 y≈0，保持 Host 构图）、
  `verticalDeadZone` 默认 0（直接跟随）；新增 `ViewWidth` 属性。
- 五个关卡 asset：`levelBottom = -900`、`levelTop = 600`（相机可跟到坑里，也够看高台）。
- `LevelRuntime`：新增 `fallKillY = -1000` 的**坠落保险丝**，低于它直接 `RestartCurrent()`。
- `LevelHost`：换到另一关时清空 `CheckpointId`；`Checkpoint.checkpointId` 统一改成场景里真实存在的对象名
  `Spring_Checkpoint`（原来是 `mu_spring` 之类，`FindByName` 永远找不到，复活点静默失效）。
- `ParallaxBackground`：背景跟着相机 y **整层平移**（不做纵向视差），上下跟随时不露边、不飘。

### 3. 地面视觉与碰撞体对不上

上一轮「背景长卷自带地面」的判断是错的：长卷是远景山水，底部是水/雾，不是玩法地面。
实际场上只有 `GroundArt` 一张 1400 宽的石台占位图，而旧 Tilemap 的 **碰撞体还开着**（按上一版的 4 块方块挡人）。

修复（`LevelLayoutBuilder`）：
- 地面碰撞体**吸附到 64 格**，和 Tilemap 的格子一致；
- 按同一组格子重画 Tilemap 并打开 `TilemapRenderer`；
- **关掉 TilemapCollider2D**（碰撞只由 `GroundSegments` 负责）；
- 关掉旧的 `GroundArt` 占位图。
- 验收截图：地面连续成条、坑宽与碰撞缺口一致；相机下潜时能看到地面侧面（Tilemap 4 行深）。

### 已知遗留

- 土/金/水一共 7 个**静态平台**（`PlatformColliders` 里保留下来的）仍然只有碰撞没有贴图。
  `tile_platform.png` 的内容只占画布下半格，直接 Tiled 会裁掉一半，所以没有硬套；

  `autoPanSpeed` 改成短时生效。

碰撞盒原来是 110×160，立绘按宽度 1.35 倍拟合后只有约 70 高、底边贴盒底 ——
**触发区顶端比花高约 90**，人在空气里被弹。已改为：

- 验收：`BoxCollider2D.bounds == Art.SpriteRenderer.bounds`（五朵全部通过，误差 < 0.2）。

### 相机

按平台跳跃的通行做法重做（死区 → 阻尼 → 预看，和 Cinemachine Position Composer 的参数一致），
`LateUpdate` 里执行：

| 参数 | 值 | 作用 |
|---|---|---|
| `horizontalDeadZone` | 140 | 角色在窗口内走动，相机不动 |
| `lookAhead` | 150 | 朝移动方向预看（按速度缓入缓出） |
| `lookAheadSmooth` | 1.6 | 预看的缓动速度 |
| `verticalDeadZoneAbove` | 80 | 脚底高过相机中心 80 才向上跟（扣掉身高 230） |

| `verticalSmooth` | 10 | 坠落时跟得比横向快，避免出画 |

死区在**屏幕空间**算，不再有「偏移 + 死区」叠加导致角色出画的问题。

- 其余空中 → 不动，只在头顶/脚底快到画面边缘时夹紧。

另外修了 `LevelHost` 换关/复活时的相机：必须 `SnapVerticalToRest()`，否则相机会保留坑底的 y，
而开场 cue 又会把它锁住（表现是复活后角色贴在画面上方）。

### 3. 小怪 0.6 体型

`MinionVisual.artScale = 0.6`，碰撞盒同比例缩到 48×78 且**底边保持 -86**（脚不浮空）。
另外 `EnemyAI` 增加 y < -1000 自动销毁：之前教学小怪会追进坑里掉到 y=-60 万，
还会永久算作「活着的敌人」，导致清场条件永远不满足。

### 4. 火的门的引导

**这不是"门坏了"**：实测两座火盆点亮、玩家走进门的感应区，门会正常打开。
玩家卡住是因为火盆美术只有「已点燃」一张，未点燃时看起来也像烧着，加上没有提示。

做了三层引导（参考平台跳跃解谜的通用做法：示能 → 分级提示 → 反馈）：

1. **示能**：未点燃的火盆压暗染色；玩家靠近时脉冲并微微提亮（一眼能看出可互动）；
2. **分级提示**（`GroupGate.lockedHints`，只在玩家被门挡住时触发，不是全局定时器）：
   - 火墙：`火墙挡住了去路` → `用攻击点燃两侧的火盆` → `两座都点亮，火墙就会熄灭`；
   - 剑气门：`剑气门封住了去路` → `切灵合态靠近剑碑共鸣，按碑上的数字顺序` → `顺序是 壹 → 贰 → 叁；点错会全部熄灭`；
   - 提示停留 5s，并高亮同组未点亮的火盆；
3. **进度反馈**：点亮一座后提示「还有一座火盆未点燃」。

### 已知遗留

- 火盆只有一张「已点燃」的美术，未点燃态靠**染色**表达（0.30 灰蓝）。若美术补一张冷/暗的待机图，
  换成两态贴图会更清楚。
- 剑碑门的提示文案已配置；剑碑本身已有「顺序错了」的反馈。

  灵雾/灵合保持 idle（飞行/悬浮不该播跑步）。同名不重播。
