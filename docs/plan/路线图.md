## 短期方案：五行关卡

当前关卡设计以 `../design/五行关卡设计v3.html` 为准：

木·青芽境 → 火·赤焰境 → 土·玄岩境 → 金·白锋境 → 水·玄泽境 → 中央祭坛。

每境遵循「教学段 → 变化段 → 综合段 → 灵泉存档 → 传送门」五拍结构，
共 **18 个机关**、**10 个碎片**、**5 枚五行印记**。

> 这与 GDD 的「四幕剧情」**不冲突**：GDD 是长期叙事结构，五行五境是现阶段先做的关卡骨架。

## 必须先解决的技术前提

### 1. 关卡不能再靠代码自建 ⚠️ 头号问题

现状：关卡几何**全部**由 `World/LevelDirector.cs` 程序化搭建（约 1000 行），
段落靠硬编码的 `x` 阈值推进（`LevelSegment` 枚举 + `SegmentOrder` 表），
道具靠 `MakeProp` / `MakeSpring` 这类辅助方法一个个摆。

这在一个 3200 宽的线性关卡里勉强能用，**撑不起 5 个境 × 每境 6 段**。

**要在下一阶段开工前定的决策**（尚未定，需要单独设计）：
- 关卡用什么承载？Unity Tilemap / 手摆 prefab / 数据驱动（ScriptableObject 或 JSON 关卡描述）？
- `LevelDirector` 退化成"读数据并搭建"，还是被完全取代？
- 关卡的**机关**用什么抽象？（现在连一个通用的机关基类都没有 —— 灵泉、屏障都是 `LevelDirector` 里手搓的）

> 结论未定前不要动 `LevelDirector`，否则会和后面的改造打架。

### 2. 平台必须先有美术

代码里已经写着这条结论：**平台必须先有美术才有意义**。
之前放过三个"只有碰撞体、没有贴图"的平台，玩家撞空气，已删。

而五行关卡是**平台跳跃**设计 —— 没有平台就无从谈起。

### 3. 地面美术是灰盒

`Main.unity` 的 `GroundArt` 指向 `Art/Textures/placeholder/platform.png`（51 KB 灰盒占位）。
所谓"地面美术横拉满整关"，拉的就是这张图。**真正的关卡美术从未存在。**

## 系统缺口（v3 需要，代码里完全没有）

| 系统 | 说明 |
|---|---|
| 传送门 / 境与境的串联 | 现在只有 `Title`/`Main`/`Ending` 三个场景硬切 |
| 碎片收集 + 印记 + HUD 显示 | 无 |
| 存档点 | 无。灵泉只回炁，不存档；**灵炁归零目前无任何后果** |
| 进度持久化 | 现有 `GameSettings` 只存设置（音量/亮度/键位），**没有游戏进度存档** |
| 通用机关框架 | 无基类 |
| 危险地形（岩浆 / 流沙 / 火柱 / 水幕） | 无 |
| 移动平台 | 无（v3 的藤台 / 浮石 / 石柱 / 磁力台 / 水流浮台全是移动平台） |
| 水位系统 | 无 |
| 近战山魈 | `EnemyAI` 本就支持近战配置（距离 72），属**配置 + 美术**，不是新代码 |

> 移动平台有个要先做小实验的问题：**Unity 里 Kinematic 刚体平台能不能带得动站在上面的 Dynamic 玩家**，
> 与摩擦设置有关。v3 有五种移动平台，方案要先定。
