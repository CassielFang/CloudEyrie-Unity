> 这一轮的现场记录：帧序列动画管线的建立、五境与 `五行关卡设计v3.html` 的差距审计、以及后续做法。

## 一、决定：放弃 Spine，改帧序列

青禾从 `SkeletonAnimation` 换成序列帧（`Resources/video_fx/青禾-<动作>/`）。
理由是程序化 IK 骨骼始终解决不了长袍遮腿、脚步滑动、以及「每个新动作都要写一遍 IK 参数」。

**格式沿用工程里已有的序列帧约定**（`小怪-行走` / `九尾狐-幻影` 那一套），不新造一种：

```
Resources/video_fx/青禾-待机/
    manifest.json          name/canvas/scale/fps/frames/loop/anchor/source/
                           layout/pageSize/pages/entries/grid
    page_00.png, page_01.png, …
```

- `canvas` = 单帧格子边长（青禾取 **384**；小怪 256、九尾狐 384）
- `anchor` = `bottom-center`，`entries` 是左上原点的页内矩形，`SequencePlayer` 负责 Y 翻转
- `SequencePlayer` 的 pivot 是**中心**，所以帧内角色位置必须逐段一致（见下面「对齐」）

## 二、生成管线（本地 ComfyUI，远端 RTX 4090）

```
立绘 美术素材/角色立绘基准版.png
  └─(裁人 + 缩放) 512² 基准帧  keyframe_qinghe_idle.png
       └─ W2: WAN 2.2 i2v 14B (Q5_K_M GGUF, lightx2v 4-step) → 1024² mp4
            └─ tools/pack_seq_atlas.py → page_NN.png + manifest.json
```

- 仓库：`~/ai/comfyui-2d-character-pipeline`（别人的开源管线，只借它的 W2 工作流）
- 驱动：`~/ai/work/run_batch.py` + `clips.json`（22 条动作的 prompt/seed/帧数）
- 打包：`~/ai/work/pack_all.py` 调 `tools/pack_seq_atlas.py`（**已入库**，补齐了丢失的 `pack_atlas.py`）

### 两个坑

1. **`WanFirstLastFrameToVideo` 首尾同图 → 几乎不动。**
   本想用它做无缝循环，但它把「从 A 回到 A」当成最短路径，输出的 81 帧几乎静止
   （帧间平均差 0.31/255）。**循环改用普通 i2v，在打包时找「与首帧最像的靠后帧」裁掉。**
2. **HuggingFace 直连超时。** 走 SSH 反向隧道用本机代理：
   `ssh -R 7890:127.0.0.1:7890`，远端 `HTTPS_PROXY=http://127.0.0.1:7890`。

### 与设计稿不符的点（按可玩性排序）

1. ~~**弓手一个都没有。**~~ **已补（2026-10-19）**：设计稿的 SVG 其实用两种颜色区分敌人
   —— 红 `#c8503c` 近战、浅蓝 `#b8c4d4` 弓手（旁边还标着「弓手」），
   而 `gen_level_layout.py` 把两种都归成了 `Enemy`。现已拆出 `EnemyRanged` 并落地：
   火 @7022、金 @7132、水 @8214（另含金境设计稿 archer@4060，场景原先没有，已补一只）。
   最终：木 5 近战 / 火 3+1 / 土 3 / 金 2+2 / 水 2+1。
   （木、土两境的设计稿里没有弓手色，所以是 0，不是漏做。）
2. **敌人总数**：木/火/土三境比设计稿多一只，那是段 0 的教学怪（重排工具刻意保留 x<900）。
   金、水与设计稿一致。
3. **五行印记 / 集齐解锁祭坛**：设计稿要求 5 枚印记点亮 HUD 圆环、集齐才开祭坛；
   当前 `Collectible` 只有碎片语义，需确认是否已有印记分支。
4. **灵炁归零无后果**：设计写「倒地回最近存档点」，代码里该事件无消费方。
5. **落坑/碰岩浆回本段起点**：设计统一规则，需查 `SegmentVolume` 是否已在跑。
6. **水位系统**：青铜水钟设计是「涨水 30s」，现为简化的「灵合敲响 → 水台升起」。
7. **沉浮浮石（站立 1.5s 后沉）与磁力平台（悬停 3s）** 目前都只是 `MovingPlatform` 的
   简单往复，没有各自的触发逻辑。

### 生成过程中定下的几条规矩（下次改动画先看这里）

1. **基准帧分两套**：常规 `keyframe_qinghe_idle.png`（人物 400/512）用于站立与循环；
   宽景 `keyframe_qinghe_wide.png`（人物 300/512、左右留白 132px）用于挥动半径大的动作。
   轻击一/二/三、重击、受击、踏云闪、灵炁爆发 走宽景——**这是把 4 条从"整段出画"救回来的关键**。
2. **出画判据有两套口径**：`qa_clips.py` 用中位帧差分（保守、易误报）；
   `pack_seq_atlas.py --min-edge` 用抠图 alpha（贴合成品）。**以打包口径为准。**
3. **`WanFirstLastFrameToVideo` 首尾同图 = 静止**，别用来做循环；循环靠打包时裁帧。
4. `pkill -f run_batch.py` 会匹配到自己那条 ssh，要用 `pkill -f "[r]un_batch.py"`。
