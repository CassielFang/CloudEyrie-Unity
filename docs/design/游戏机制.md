# 《云岫》当前机制详解

> **这份写的是「代码里实际生效的东西」**，不是设计意图。
> 设计意图见 `Cloud Eyrie.md`（GDD）与 `五行关卡设计v3.html`（当前关卡方案）。
> 两者与本文不一致时，**以本文为准** —— 本文每条都对着代码核过。
>
> 具体数值（消耗、伤害、速度、半径…）**不在这里**，见 `数值.md`（唯一真相源）。
> 最后校对：2026-10-12（Unity 版）。

---

## 一、一句话

2D 横版动作。**青禾与灵伴莹翳共享一条「灵炁」**，靠三形态切换解谜与战斗。
当前可玩内容是一段线性关卡 + 一场三阶段九尾狐 Boss 战。

---

## 二、核心资源：灵炁

**唯一资源条。**所有动作、形态、技能都从它扣，**没有血条** —— 挨打扣的就是灵炁。

- 灵炁**归零目前无后果**。设计上是"倒地回最近的存档点"，尚未实现
  （`GameEvents` 里那条"灵炁归零"事件**无任何消费方**）。

**「战斗中」是集合，不是开关**：`SpiritEnergySystem.SetCombatSource(this, true/false)`，
同屏多只敌人各报各的，任一只在场就算战斗中。

> ⚠️ **销毁敌人时必须退订**，否则那条记录永远留着，灵炁永久停在战斗恢复档。
> 同类的坑还有一个：灵泉的"在泉中"是 **static**（跨场景活着），关卡重建时必须先无条件清掉，
> 否则会出现"灵雾形态完全打不出灵弹且无法自愈"。

---

## 三、三形态

青禾与莹翳共享一条灵炁，**形态切换是这套玩法的核心约束**。

| 形态 | 怎么进 | 能力 | 限制 |
|---|---|---|---|
| **实体** `Entity` | 默认 | 走 / 二段跳 / 踏云闪 / 近战三连 / 蓄力重击 / 格挡 | 灵炁低于阈值强制变灵雾 |
| **灵雾** `Mist` | 切换 | 八向自由飞行、**穿过灵界屏障**、灵弹远程 | 持续消耗灵炁；无法近战 |
| **灵合** `Merge` | 需灵炁 ≥ 门槛 | 悬浮移动、**净化光环**、**灵炁爆发** | 冷却 + 持续消耗；有冷却闸 |

**三形态不切换碰撞层** —— 玩家身体恒为 `PLAYER` 层。
"灵雾穿墙"是**关卡侧按形态开关屏障的碰撞体**，不是改层。

任何切换都有固定硬直；灵炁不足时**先查后扣**，扣不起就不起手（并给出提示，不静默失败）。

## 四、青禾的战斗动作

| 动作 | 用途 |
|---|---|
| **轻击三连** | 连点攻击键。三段伤害递增，第三段带击退。**连击窗口从「收招」计时** |
| **蓄力重击** | 按住攻击键蓄力，松开释放。分半蓄 / 满蓄两档，高伤害高消耗，Boss 硬直窗口的最佳输出 |
| **踏云闪** | 冲刺闪避。**需已起跳**（沿用"二段跳的第二跳即踏云闪"的早期设定）；扣灵炁 |
| **格挡 / 完美格挡** | 按住格挡减伤；命中前极短窗口内按下 = 完美格挡，**不扣灵炁并反制敌人** |
| **二段跳** | — |
| **灵弹** | 仅灵雾态。远程消耗手段，也是 Boss P1 识破真身的主要工具 |

> ⚠️ 连击窗口**从收招计时**是修过的老坑：从起手算的话窗口(0.3s) < 攻击时长(0.4s)，连段永远接不上。

## 五、敌人：阳浊小怪（持弓）

**一个组件 `EnemyAI` 管全部小怪**，是**手写扁平状态机**（巡逻 → 发现 → 追击 → 攻击 → 死亡），
外加一层优先级更高的**受击硬直**。**不是行为树** —— `archive/团队日志/` 里那份行为树设计文档从未落地。

- 近战 / 远程靠 `Ranged` 字段区分；远程型射的是真正的抛射物（`MinionArrow`），不是近身结算。
- **动画与逻辑是同步的**：远程攻击总时长与拉弓动画对齐，**箭在动画的放箭帧才生成**，不是各按各的计时器。
- **个体差异不配数值**：`Core/Personality.cs` 用固定种子只错开行为时间/相位
  （反应快慢、停留长短、攻击间隔、巡逻偏好），数值完全相同。

> ⚠️ **远程型的视野必须大于射程**。两者相等 =「看得见＝够得着」→ 一进视野直接开打、永远不走过来
> （表现是"发现玩家后返回巡逻就不走路了"）。

**阴浊型敌人未实现**（GDD 里"普攻无效、须先显形"的那类），只有配置字段占位。

## 六、Boss：九尾狐（三阶段）

| 阶段 | 名称 | 血量区间 | 核心机制 |
|---|---|---|---|
| P1 | **幻影** | 100% → 70% | 分裂成三身，**未识破前免伤**；切灵雾飞近任一身 → 整组识破 |
| — | 转场 | — | 全屏动画 |
| P2 | **狂乱** | 70% → 35% | **浊湮领域**（铺满战场，逼玩家浮空）+ **狐火**（召唤物，追人） |
| — | 转场 | — | 全屏动画（莹翳强制灵合） |
| P3 | **归心** | 35% → 10% | **强制灵合**，靠净化光环 / 灵炁爆发输出 |
| — | **哀鸣** | ≤ 10% | 停止攻击，等着被净化 |
| — | 已净化 | — | 播最终净化动画 → 切结局场景 |

**P1 的玩法循环**：Boss 分裂三身 → 玩家怎么打都无效 → 切灵雾飞近识破
（真身显灵炁纹路、假身压暗）→ 切回实体输出。**重排会作废识破**，所以要反复"识破 → 输出"。

**实现上的一处简化**：真身永远是挂 `BossAI` 的根节点，另两身是程序化建的诱饵（只有立绘，无碰撞与血量）。
代价是**打在诱饵上的刀会穿过去、没有打击反馈**。

> ⚠️ **P2 的「尾焰弹幕」没有实现。** 它只出现在 `BossAI` 的类型注释里（设计意图），
> 实际 `EnterP2` 只做了浊湮领域 + 狐火波次。写文档时别把它当成已有功能。
>
> ⚠️ **九尾狐没有任何挥击/甩尾的骨骼动画**（美术只给了幻影/狂乱/归心三段**形态**动画），
> 所以它的"攻击"必须靠**召唤物与弹幕**表达 —— 狐火正是补这个位置的。

## 七、关卡

**《云岫》**，当前是**线性推进的一关**，横向 `0 ~ 3200`，出生点 `x = 200`。

| 段 | 内容 |
|---|---|
| 0 开场过场 | 相机锁定，背景缓慢推移 |
| 1 前奏探索 | 两只阳浊小怪 |
| 2 灵雾教学 | 灵界屏障挡路，须切灵雾穿过 |
| 3 过渡段 | 灵泉石台（靠近回灵炁） |
| 4 Boss 战场 | 相机锁定，Boss 开打 |

> ⚠️ **关卡几何全部由代码搭**（`World/LevelDirector.cs`），这是比赛期赶工期的临时决策。
> **整关没有一个平台** —— 代码里写着「平台必须先有美术才有意义」。
> 下一阶段要改成可编辑的关卡资源，见 `../plan/路线图.md`。

### 相机与背景

- **相机直接移动 `Canvas/Camera`**（不是移动世界根节点 —— 那样会和玩家刚体打架）。
  探索段跟随玩家并夹在关卡两端；Boss 战场锁定并让背景缓慢平移。
- 代价：HUD 会被推走，所以屏幕固定的东西挂 `World/ScreenFixed` 反向补偿。
- 背景是**卷轴式视差**（远景 / 中景 / 散布山峰 + 自漂移）。
  图层宽度由相机行程反推：`视口宽 + 系数 × 行程`，少给会在关卡末尾露空。

### 物理分组

玩家与小怪**彼此不阻挡**，但刀砍得到 —— 靠碰撞矩阵实现，详见 `../../CLAUDE.md`。

## 八、素材与动画

美术组交的是**视频**，引擎要的是**图集序列**。三步流水线在 `tools/`：

```bash
python gen_video_fx.py --export      # 视频 → PNG 序列（抠背景 / 接循环 / 主体等大）
python pack_atlas.py --scale 0.5     # 序列 → 图集页 + 索引 → Assets/Resources/video_fx/
python extract_arrow.py              # 特例：从攻击动画里抽独立抛射物
```

播放由 `Fx/SequencePlayer` 负责，**滑动窗口页缓存**（只驻留播放头附近的页）。
`MinionVisual` / `BossAI` / `FogFire` 按状态驱动它播哪一段、从第几帧到第几帧。

- **青禾目前是 Spine**，但**只有 `idle_breath` 一条动画** —— 走路 / 跳跃 / 攻击都还没有。
  所以目前**三形态靠水墨粒子配色区分**（这不是纯装饰，是玩法可读性的一部分）。

## 十、键位

移动 **A/D**、二段跳 **Space**、攻击/蓄力 **J**、踏云闪 **K**、格挡 **L**、
实体↔灵雾 **F**、灵雾→灵合 / 灵合→实体 **G**。

改键在首页「设置」页。输入走 `Core/InputSystem.cs` 的动作层
（动作定义在 `InputActions.cs`，加动作只需在那里加一个分支，不用迁移存档格式）。
