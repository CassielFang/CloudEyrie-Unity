### 6.1 关于踏云闪「需已起跳」

代码里 `EntityForm` 的冲刺条件带 `jumpCount >= 1`，来自 GDD 早期设定「二段跳的第二跳即踏云闪」。
规划 v2.0 把踏云闪改成了**独立闪避键（K，无需起跳）**，两边不一致。

**当前保留「需已起跳」**，因为改成地面也能冲会直接影响手感与关卡节奏，属于设计决策，**待团队确认后再动**。
若要改，只需去掉 `EntityForm` 里的 `this.jumpCount >= 1` 条件（一行）。

输入事件名（临时）：`[Combat][diag]` 之外，攻击相关日志前缀统一为 `[Combat]`。

## 8. 已知的坑（改代码前先读）

| 坑 | 说明 |
|---|---|
| **判定盒碰撞体 offset 必须为 0** | `CombatController` 只翻转**节点位置**做左右镜像，`BoxCollider2D.offset` 不跟着翻。`onLoad` 会把 offset 折进节点位置并归零做兜底，但别在 Inspector 里设 offset |
| **命中盒刚体类型必须是 `Animated`** | `Static` 的 fixture 不跟随节点移动；`Dynamic` 会休眠（休眠后接触事件不触发）。两者都会导致"攻击时灵时不灵" |
| **连击窗口从收招计时** | 若改回从起手计时，窗口(0.3s) < 攻击时长(0.4s)，连段永远不会接上 |
| **换美术素材要改「天然朝向」常量** | `QingheController.ART_NATURAL_FACING`（当前 `1`＝朝右）、`CombatController.SLASH_NATURAL_FACING`（当前 `1`）。判错会导致"攻击打到背后" |
| **预览运行时无法保存场景** | 必须先停止预览再 `Ctrl+S`，否则 `save` 会"看起来成功"但文件不写 |
| **游戏字体缺「炁」字** | `assets/resources/font.ttf`（`chengrongguangke`）的 cmap 里**没有 U+7081「炁」**。给 Label 挂这个字体时，「灵炁」会掉字。首页文案已避开；写新 UI 文案前先确认 |
| **`Sprite.spriteFrame` 赋值会重置节点尺寸** | 赋 `spriteFrame` 时若 `sizeMode` 还是默认值，节点 contentSize 会被改写成贴图尺寸（且图片导入会自动裁掉透明边，实际尺寸常与源文件不同），之后再把 `sizeMode` 设成 `CUSTOM` **不会恢复**你设的值。要设尺寸请放在最后，或按节点当前 contentSize 反算缩放 |
| **`LabelOutline` 组件在 3.8.2 起已废弃** | 改用 `Label.enableOutline` / `outlineColor` / `outlineWidth`。浅色文字压在明暗不定的山水画上必须描边，否则糊进云里 |
| **运行时建的 `BoxCollider2D` 必须调 `apply()`** | `size` / `offset` 的 setter **只存值，不重建 Box2D 夹具**（engine `box-collider-2d.ts`）。夹具要到 `apply()` 里才按 `comp.size` 重新 `SetAsBox`。不调的话物理世界里一直是字段默认的 **`Size(1,1)`** —— 一个 1×1 像素的碰撞体，角色从针尖上穿过去。场景里序列化好的碰撞体没这问题（`onLoad` 时 `_shape.onLoad()` 会读到正确尺寸），**只有运行时新建的才会踩** |
| **`col.size` / `col.worldAABB` 会骗人** | 上一条的帮凶：两者都是从 JS 字段算的，夹具即使还是 1×1 也照样报「3200×80」。排查碰撞问题**不能用几何读数**，要用行为判据（比如每秒打一次角色 y）。为此白跑过两轮预览 |
| **`.webm` 不被识别为 `cc.VideoClip`** | Cocos 3.8.8 的 `video-clip` 导入器只认 `.mp4` 一族，`.webm` 会被导成 `importer:"*"` / `cc.Asset`。而 Web 上能带 alpha 的视频基本只有 VP9/WebM —— 所以**透明视频这条路走不通**。（另外 Web 端 `VideoPlayer` 是 DOM `<video>` 元素，画布里的东西盖不到它上面。）全屏过场只能用 PNG 序列 |
| **别把高分辨率序列帧全量塞进 `assets/`** | 九段视频按原规格打包成 723 页、15.8 亿像素，解成 RGBA 约 **5.89GB**。编辑器要为每个资源建导入项、选中大图还会上传贴图，GPU 显存一紧 Chromium 就把 WebGL 上下文丢掉（反复弹「WebGL 上下文丢失」）。现在按半分辨率打包（`pack_atlas.py --scale 0.5`），降到 1.46GB |
| **敌人碰撞体宽度必须小于两倍攻击距离** | 小怪是「走到 `attackRange` 就停下开打」的。碰撞体一旦宽过 2×攻击距离，它就会一边"停在攻击距离"一边把玩家顶开 —— 实测反馈「人物被小怪挤跑」。main.scene 原本那只用的是 64×110（半宽 32 < 72） |
| **传感器之间不产生接触** | `AttackHitBox` 是 sensor，靠接触事件维护重叠集合。所以**敌人碰撞体不能也做成 sensor**（那样玩家就再也打不到它了）。要让玩家与小怪彼此不阻挡，得走碰撞矩阵 —— 见 `core/PhysicsGroups.ts` |
| **`QingheController.groundNode` 是节点引用** | 着地判定写死了 `otherCollider.node === this.groundNode`。**地面必须是场景里的那个节点**，运行时另造一个它指不到 —— `grounded` 永远 false、`jumpCount` 永不重置，表现是「跳两次之后再也跳不起来」（一度被误读成"接触小怪后不能跳"） |
| **`sp.Skeleton` 与 `cc.Sprite` 不能同节点** | 两者都是 UIRenderer，`addComponent` 直接报冲突，而 `removeComponent` 是延迟生效的、当帧也加不进去。换骨骼动画的做法是**另建一个仍叫 `Art` 的节点**（`QingheController` 按名字找立绘，改名会让朝向翻转失效） |
| **`sp.Skeleton` 不听 `UITransform` 的 contentSize** | 尺寸只能靠节点 scale 压。青禾 setup pose 约 1370 Spine 单位高，取 0.27 才约 370 世界单位（比例与碰撞体 150 相称）。**别靠截图估** —— 从骨骼数据算 setup pose 包围盒更准 |
| **`Animated` 刚体忽略 `linearVelocity`** | `Animated` 由节点变换驱动，写速度**完全无效**。抛射物要用 **Dynamic**（照抄 `MistShot.buildFallbackShotNode`：`gravityScale=0` + `bullet=true`）。用错的表现是「箭生成后钉在空中不动、也永远打不到人」 |
| **`@property` 的默认值会冻结进场景** | 组件加进场景的那一刻，`@property` 的默认值就写成**序列化数据**了。之后改代码里的默认常量（如 `DEFAULT_SCENERY`）**对已存的场景毫无影响** —— 必须改场景里的值。排查时先看 `.scene` 里存的是什么 |
| **给 `@property` 数组的元素加字段，老场景补不上** | 上一条的加强版，也更阴：数组是**逐个元素整体**序列化的，给 `LayerSpec` 这种元素类型新加一个键（如 `drift` / `height`），已存场景里那份旧数组**没有这个键**，而 Cocos **不会**像组件属性那样用类默认值去补 —— 新字段在运行时恒为 `undefined`。症状是「改了默认值但画面纹丝不动」，且**只有老场景复现、新建场景正常**，很容易误判成别的原因（`ParallaxBackground` 的 `drift` 白找过一轮）。解法是运行时按元素身份（这里是 `path`）去 `DEFAULT_*` 里把缺的键补上 —— 见 `ParallaxBackground.mergeDefaults` |
| **`getComponent` 取不到「挂在别的节点上」的组件** | 它只找**本节点**。`LevelDirector` 在 `Level` 节点上、而 `ParallaxBackground` 挂在 `Canvas/Background`（背景要在小怪之下，不能同节点）—— `this.getComponent(ParallaxBackground)` 恒为 `null`，于是 `autoPanSpeed` 从没被设过，「开场远景推进 / Boss 战场背景平移」全程静默失效。跨节点一律走 `scene.getChildByPath(路径).getComponent(...)`，并且**取不到时要 `warn`**，别再让它静默 |
| **子节点必须在依赖它的组件之前建** | `EnemyAI.onLoad` 里 `getChildByName('Art')` 是**一次性**查找。先 `addComponent(EnemyAI)` 再建 `Art` 子节点 → 拿到 null → 朝向翻转整个失效（表现「小怪不会转身」）。和 `groundNode` 那条是同一类：**运行时的节点引用必须在正确的时机取** |
| **每个敌人可能有各自的天然朝向** | `ART_NATURAL_FACING` 原本是 `EnemyAI` 的模块级常量，但持弓的阳浊小怪素材是**朝左**画的（`-1`）、灰盒敌人朝右（`1`）。已改成每实例的 `artNaturalFacing`。传错整个左右反掉 |
| **远程敌人要离出生点比射程更远** | 射程 460、出生点 x=200，把小怪摆在 640 → 距离 440 < 460，**一进场就被发现、立刻挨一箭**。按「最坏情况」算：位置 − 巡逻范围 − 出生点 > 射程 |
| **回调不能设在内部 `stop()` 之前** | `SequencePlayer.play()` 里先 `this.onComplete = cb`、`start()` 里再 `stop()`，而 `stop()` 有一句 `this.onComplete = null`（给外部取消用）—— **刚设的回调被自己清掉**。症状离现场很远：`MinionVisual` 的「攻击播完回走路」不触发 → 小怪永久卡成一帧静止图；`StageTransition` 的 `onComplete` 也不触发 → Boss 转场永远不推进阶段。凡是「回调不生效」先查这里 |
| **远程型的视野必须大于射程** | 两者相等＝「看得见就够得着」→ 一进视野直接开打、永远不走过来（表现「发现玩家后返回巡逻就不走路了」）。取射程的 1.5 倍。追击脱战线也要按**有效视野**算，不能用基础 `sightRange` |
| **一段角色可能有多套素材、朝向未必一致** | 美术组交的「小怪-行走」朝右（弓在右、箭囊在左）、「小怪-攻击」朝左，**同一只小怪的两段动画左右相反**。没有任何单一 `ART_NATURAL_FACING` 能同时满足 → 必须在**流水线里镜像**统一（`gen_video_fx.py` 的 `VIDEOS` 第 4 项）。**接新素材时先并排比一眼朝向** |
| **动画暂停要按「有没有真在动」，不是按状态** | 巡逻的到点停留、攻击冷却时都是「状态没变但人站着」。按状态切会让它原地踏步 —— 应取刚体速度判定，站住时 `pause()`、动起来 `resume()` |
