# 设置页接口说明

> 相关代码：`ui/SettingsPanel.ts`（设置页界面本身）、`ui/TitleSubPanels.ts`（面板框架）、
> `core/InputActions.ts`、`core/InputSystem.ts`、`core/GameSettings.ts`、`audio/AudioManager.ts`

## 一句话总览

| 要做的控件 | 调什么 | 谁负责持久化 |
|---|---|---|
| 音量滑条（主音量 / 音乐 / 音效） | `audioManager.setChannelVolume(...)` | 自动 |
| 键位列表 + 重映射 | `inputSystem.getBindings(...)` / `inputSystem.rebind(...)` | 自动 |
| 恢复默认 | `audioManager.resetAudio()` / `inputSystem.resetBindings()` | 自动 |
| 想跟着设置变化刷新 UI | `eventBus.on('settings-changed', ...)` | — |

**所有写入都会自动落盘**（localStorage），界面不需要自己存。

> ✅ 这一页**已经实现**了 —— 见 `ui/SettingsPanel.ts`（下文第 5 节是它的说明）。
> 接口部分仍然照本文档调，界面只跟 `audioManager` / `inputSystem` 说话，不直接碰 `gameSettings`。

## 1. 音量

```ts
import { audioManager } from '../audio/AudioManager';

audioManager.setMasterVolume(0.8);        // 主音量，0~1
audioManager.setChannelVolume('bgm', 0.6); // 音乐
audioManager.setChannelVolume('sfx', 0.9); // 音效

audioManager.getMasterVolume();            // 读回来给滑条定位
audioManager.getChannelVolume('bgm');
audioManager.getEffectiveVolume('bgm');    // 实际生效值 = master × bgm

audioManager.resetAudio();                 // 三档一起回默认（主 0.8 / 音乐 0.7 / 音效 0.8）
```

- 三个分组：`'master'` / `'bgm'` / `'sfx'`，取值都是 `0~1`，超范围会被夹住。
- 默认值：master 0.8、bgm 0.7、sfx 0.8。
- 滑条直接用 `getXxxVolume()` 初始化，拖动时调 `setXxxVolume()` 即可，**不需要去抖也不需要手动保存**。
  默认值表在 `GameSettings` 里是私有的，所以「恢复默认」走 `audioManager.resetAudio()`，别在 UI 里硬编码 0.8/0.7/0.8。
- ⚠️ `setVolume` 每次都会**同步写一次 localStorage** 并广播。拖动时逐帧调会很浪费，
  设置页的做法是：视觉按鼠标位置逐帧画，**落盘按整数百分比限频**，松手时再补一次精确值。

> ⚠️ **现在拖动滑条听不到任何变化** —— 项目里还没有音频素材，`AudioManager` 的播放部分是空实现。
> 音量这条链路本身是真的（能存、能读、能算），等音频素材接入后自动生效，届时界面不用改。

## 2. 键位

```ts
import { inputSystem } from '../core/InputSystem';
import { ALL_ACTIONS, ACTION_LABELS, bindingLabel, key } from '../core/InputActions';
import { KeyCode } from 'cc';

// ① 列出一行（做列表用）
for (const action of ALL_ACTIONS) {
    const title = ACTION_LABELS[action];                        // 「跳　跃」
    const keys  = inputSystem.getBindings(action).map(bindingLabel);  // ['空格']
}

// ② 改一条绑定（index 见上，越界返回 false）
inputSystem.rebind(action, 0, key(KeyCode.KEY_K));
inputSystem.rebind(action, 1, { kind: 'key', key: KeyCode.KEY_L });

// ③ 单行 / 全部恢复默认
inputSystem.rebind(action, 0, DEFAULT_BINDINGS[action][0]);
inputSystem.resetBindings();
```

- `ACTION_LABELS` 是动作的中文名，**别在 UI 里再手写一份**，否则改动作名会两边不同步。
- `bindingLabel(b)` 把绑定转成可读文本（`空格` / `回车` / `D` / `↑`…）。
- `DEFAULT_BINDINGS` 是出厂绑定表，做「单行恢复默认」时读它。
- 改完会立即生效并落盘，**不需要重启或重载**。

### 捕获模式（已实现）

捕获「玩家按下的下一个键」时，**动作层同时也是活的** —— 玩家为了把「跳跃」改成 K，按下 K 的那一刻会同时触发「踏云闪」。所以 `InputSystem` 有一个捕获模式：

```ts
inputSystem.setCaptureMode(true);    // 进入捕获：动作层停止记录按键
// ... 玩家随便按一个键，UI 自己接 input.on(Input.EventType.KEY_DOWN) 拿它 ...
inputSystem.setCaptureMode(false);   // 退出捕获：动作层恢复
inputSystem.isCapturing;             // 当前是否在捕获（UI 用它判断按键归谁）
```

- 进入/退出都会清一次按键状态：玩家为了改键按住不放的那个键（例如按住 D 去改「向右移动」）
  不清掉的话，退出捕获后主角会自己往右走。
- ⚠️ **用完必须退出**。捕获模式下 `keysDown` 永远是空的，等于整个动作层哑掉 ——
  关闭设置面板却忘了退，表现就是「游戏里按键全没反应」。
  三重保险：设置页关闭/重建/场景卸载都会退（`SettingsPanel.dispose`），
  另外 `InputSystem.reset()`（切场景、失焦时自动调）也会把它放掉。
- **别绕过它直接在 UI 里读原始按键**，否则上面那个坑一定会踩。

## 3. 数据与持久化

- 存档键：localStorage 的 `yunxiu.settings`，内容是一段 JSON。
- 结构：`{ version, audio: {master,bgm,sfx}, bindings }`；`bindings` **只存被改过的动作**，没改过的读的时候回落到 `DEFAULT_BINDINGS`（这样以后调默认键位，老玩家不会被旧默认值钉死）。
- 读盘全程有保护：JSON 坏了 / 字段缺失 / 版本比代码新 → 回落默认值并打 warn，**不会因为一份坏存档卡死游戏**。
- ⚠️ **`sys.localStorage` 目前只在 Web 端有实现**。打包成原生 App 后设置不会持久化（存储后端已抽成一层，原生分支留了 TODO 要接 `native.fileUtils`）。

## 4. 想知道设置什么时候变了

```ts
import { eventBus } from '../core/EventBus';
import { SettingsChangedEvent } from '../core/GameSettings';

eventBus.on<SettingsChangedEvent>('settings-changed', (e) => {
    if (e.audio) { /* 刷新音量滑条 */ }
    if (e.bindings) { /* 刷新键位列表 */ }
});
```

> 回调必须是**箭头函数属性**（`private onXxx = (e) => {...}`）或显式 bind —— `EventBus` 不传 target，普通方法里的 `this` 会是 `undefined`。

⚠️ **必须成对 `eventBus.off`**。`eventBus` 是模块级单例、活得比场景久，而设置页是普通工具类
（没有引擎生命周期，`onDestroy` 不会自己找上门）。不摘的话切场景后设置一变，回调会摸到已销毁的节点。
设置页的摘除点是 `SettingsPanel.dispose()`，由 `TitleSubPanels` 在**打开前、关闭时、场景卸载时**三处调用。

> 顺带一条踩过的坑：**判断节点是否还有效，要查组件自己的 `.isValid`，不要写 `x.node.isValid`** ——
> 组件销毁后 `node` 会被置成 `null`，读 `.isValid` 直接抛 `Cannot read properties of null`。
> 场景卸载时 `dispose()` 正是跑在销毁过程中，实测刷了 5 条报错。

## 5. 设置页界面（`ui/SettingsPanel.ts`）

**普通工具类**（不是 Component），由 `TitleSubPanels.buildSettings()` new 出来。只管把上面的接口接到界面上，
自己**不存任何状态** —— 每次渲染都从单例现读，所以切页签整个重建节点也不会丢东西。

### 版式

两个页签（音量 / 键位），面板可用区 1000×620，上下墨线在 `y = ±249`：
标题在天头留白带（`+282`），「按 E 退 出」与它镜像放在地脚留白带（`-282`）—— 三个子面板共用那一行。

- **音量页**：三行，行距 115。每行 = 标签（右对齐，右缘 `-220`）+ 滑条（中心 `x=55`，槽长 420）+ 百分比（左缘 `+320`）。
- **键位页**：**只列 10 个游戏内动作**（行距 32），每行固定 **2 个槽位**。
  菜单那三个动作（上移/下移/确认）故意不列 —— 平时改不到，列出来只是占地方；
  它们仍在 `ALL_ACTIONS` 与存档里，`checkActionGroups()` 会盯着别漏。
  槽位列数固定而不是「有几个画几个」：方向键有 2 个绑定、其余 1 个，
  按实际数量画会参差不齐。**改动作的绑定数时留意别超过 2 个**，超了会被静默吃掉一条（自检会报）。
- 页脚「恢复默认」按钮与改键提示**共用同一个位置**，按状态二选一显示（不是定时器，是状态）。

### 滑条是自己画的，没用 `cc.Slider`

引擎 Slider 的 `handle` 必须是 `Sprite`、还得在代码里搭节点树，样式也迁就它的默认观感；项目里零先例。
这里直接用 `resources.load('white/spriteFrame', SpriteFrame)` 染色的横条（同 `ui/DebugHud.ts` 的做法）
+ `Graphics` 画的菱形把手，交互自己处理：点槽直接跳值、拖动跟手。

> ⚠️ **拖动必须用节点级 `TOUCH_START/MOVE/END/CANCEL`，不能用全局 `input.on(MOUSE_MOVE)`**。
> 引擎的派发器链是「返回 false 就 break」（`Input._emitEvent` 里 `if (!dispatcher.dispatchEvent(event)) break;`），
> 而 UI 派发器 `PointerEventDispatcher` 优先级更高：节点在 `TOUCH_START` 里**认领**（claim）这个 touch 之后，
> 事件就被它吞掉，**全局监听器一次都收不到** —— 症状是「按下能跳值、拖动完全不跟手」。
> 认领之后 `TOUCH_MOVE` 会**跳过命中测试**直接发给该节点，所以拖出滑条范围照样跟手，
> 松手也不需要另挂全局监听。引擎自带的 `Slider` 就是这么做的。

> ⚠️ 另外两个踩过的坑：
> 1. `Sprite.spriteFrame` 赋值会把 contentSize 重置成贴图尺寸，**先赋 frame 再设尺寸**。
> 2. 拖动期间页面可能被重建（切页签、关面板）。旧节点的 `UITransform` 一旦销毁，
>    `convertToNodeSpaceAR` 会**每次移动都抛一次**，拖动看起来像卡死、日志被刷屏。
>    所以 `applyDrag` 里要自查 `box.isValid`，并且**切页签时必须清掉 `dragging`**。

### 改键流程

点槽位 → `setCaptureMode(true)`，槽位文案变「按新键…」、页脚换提示 → 按下一个键 → `rebind` 落绑定。
按 E 取消。**顺序要紧：先退捕获再 `rebind`** —— `rebind` 会广播 `settings-changed` 并同步回调刷新，
还处在捕获态的话刷新会把「按新键…」冲掉。

同一动作内部查重（复用 `sameBinding`），**跨动作重复是合法的**（↑/W 同时是「向上」与「菜单上移」），不拦。
不提供清除绑定 / 添加第二个绑定 —— `GameSettings.setBinding` 对越界 index 返回 false，
且 `validateBindings()` 把空绑定当错误，要支持得先改 `GameSettings`。

### 返回键的优先级

返回 / 取消**统一用 `PANEL_BACK_KEY`（E），不用 ESC** —— Web 上游戏是全屏跑的，而 ESC 是
浏览器保留的「退出全屏」键（页面拦不住），用它当返回会「一边关面板一边掉出全屏」。
这个常量只有一份定义，在 `ui/ScreenStage.ts` 里：面板文案、`TitleScreen`（关面板）、
`SettingsPanel`（取消改键）三处都读它。

改键捕获中 E = **取消改键**，不是退出面板。所以 `TitleScreen.onKeyDown` 在 Panel 阶段
**先问面板**（`TitleSubPanels.handleKeyDown(e)` 返回是否消费），没被消费的 E 才走 `closePanel()`。
